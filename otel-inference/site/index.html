LLM slow? Make one dashboard answer it.

vLLM already emits the signals. Nobody has agreed on their names — so you can't build one causal view that decomposes a latency spike, or reuse it on the next engine. This is a candidate gen_ai.server.* convention that fixes that.

OpenTelemetry-native · maps to semantic-conventions-genai #87 · runs on a free Kaggle T4

the read

Symptom on top. Cause underneath.

Existing write-ups stop at "scrape /metrics, draw gauges" — that shows you a spike, not its reason. The convention lines up four causes under one symptom, so a red line decomposes instead of just alarming.

symptom
request.duration p99
Something is slow. Read down before you page anyone.
├─ decomposes into ─┐
cause · scheduler
queue.wait_duration
Requests are piling up — arrivals outrunning the batch. Leads the latency line.
cause · cache
kv_cache.hit_rate
Every miss becomes prefill compute. Computed as rate(hits)/rate(queries), never a stored gauge.
cause · phase
prefill vs decode
Which phase is the wall. Prefill-bound → prompt/cache. Decode-bound → throughput/GPU.
cause · hardware
gpu.utilization
Compute wall or not. From a pynvml sidecar — the one signal /metrics omits.

Then you click the spike and land on the individual slow trace, whose gen_ai.latency.time_in_queue confirms the story. Aggregate metric → single trace, one investigation.

the primitive

The whole trick is a rename.

An OTTL block in the OpenTelemetry Collector rewrites each engine's raw metric names into the shared convention. Adding an engine is adding where clauses — the dashboard and alerts never change.

collector/ottl/vllm.yaml — transform/genai_convention
# raw vendor name                          shared convention
set(name, "gen_ai.server.kv_cache.hits")        where name == "vllm:prefix_cache_hits"
set(name, "gen_ai.server.kv_cache.queries")     where name == "vllm:prefix_cache_queries"
set(name, "gen_ai.server.queue.wait_duration")  where name == "vllm:request_queue_time_seconds"
set(name, "gen_ai.server.prefill.duration")     where name == "vllm:request_prefill_time_seconds"
set(name, "gen_ai.server.decode.duration")      where name == "vllm:request_decode_time_seconds"

reproduce it

A latency incident, on purpose, for free.

warm

Shared-prefix prompts, low concurrency. Hit-rate high, queue empty — the healthy baseline.

spike

Unique long prompts, high concurrency. Hit-rate collapses and the queue backs up. TTFT and e2e latency spike.

recover

Back to shared prefixes. Cache warms, queue drains, latency returns. Cause visible the whole way down.
